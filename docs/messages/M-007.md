## 1. HOTFIX-1 (BLOCKING, C# lane, first thing today)
The PO installed the latest installer on his Windows PC and pressed "Start automatic setup" on the MAUI setup page. Result (screenshot): "خطا در راه‌اندازی خودکار: فایل Kandoo.Hub.exe در پوشه نصب یافت نشد."
**Cause (read from `src/Kandoo.App/SetupWizardPage.xaml.cs` on `arena/kandoo-c92-customer-mode`):** `ConfigureShopAsync` takes `appDir = dirname(Environment.ProcessPath)` and looks for `appDir\hub\Kandoo.Hub.exe`. Since C-95 the process is `{install}\app\Kandoo.App.exe`, so the code looks in `{install}\app\hub\`, but the installer puts the Hub in `{install}\hub\Kandoo.Hub.exe` (layout v2, `packaging/HubPilot/KandooHub.Installer.iss`). The old WinForms launcher lived in the install root; the code was ported without adjusting the path.
**Fix:**
- Extract path resolution into a small class (for example `HubLocator`) that returns the Hub exe: first `..\hub\Kandoo.Hub.exe` relative to the app folder, then `.\hub\Kandoo.Hub.exe` (dev layouts). On failure the error message must list every path that was checked.
- Unit tests for both layouts and for the not-found message.
- Search the whole app for other uses of `ProcessPath` / `AppContext.BaseDirectory` that assume the old launcher location and fix them the same way.
- Add a headless self-check to the app: `Kandoo.App.exe --self-check` runs BEFORE any UI is created: resolves the Hub, starts it on a free port with a bootstrap proof, performs the owner-session call, prints one line `KANDOO_SETUP_OK port=<n>` to stdout and to the file passed as the next argument (if any), stops the Hub, exits 0; on any failure prints `KANDOO_SETUP_FAIL <reason>` and exits 1. Tell the PM the exact argument format in R-007; the PM updates `scripts/Invoke-InstallerSmoke.ps1` to call it against the INSTALLED folder, so this class of bug is caught by CI.
- Push the fix on `arena/kandoo-c95-maui-launcher` and merge that branch into the stacked branches (c90, c91, c92, C-96). Report branch, SHA and run URL.
