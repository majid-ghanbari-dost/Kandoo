# C-40 — First real MAUI review-queue gate

**Scope:** one .NET MAUI project for Windows and Android, one review-queue screen, REAL/FAKE data sources, shared design tokens, pinned local Vazirmatn fonts, source-linked xUnit logic tests, and a path-scoped app workflow. `Kandoo.App` and `tests/Kandoo.App.Tests` are intentionally outside `Kandoo.sln`; `.github/workflows/ci.yml` remains unchanged. Avalonia remains the retained fallback and was not substituted.

## Delivered behavior

- REAL mode calls bearer-authenticated `GET /v1/stores/{store_id}/reviews` with an in-app configurable Hub base URL, store ID, and session token. FAKE mode is zero-config and displays a persistent visible `داده نمایشی` banner. Switching modes clears the previous rows so fake data cannot be presented as real.
- Queue rows map the existing `source.header.invoice_number`, `source.header.captured_at`, `source.summary.payable`, and `queue_status` fields. Rows show invoice number, Jalali date, REVIEW/ISSUED state, and integer Iranian Rial (`IRR`, `ریال`) amounts. The Hub unit is the C-33 finding: `HubInvoiceCurrency.Code=IRR` and invoice items are Rial amounts. Missing dates use an honest not-recorded marker.
- `src/Kandoo.Core/JalaliDateConverter.cs` centralizes the existing C-33 `PersianCalendar` and Asia/Tehran approach; C-33 stats now consumes the same helper. No calendar arithmetic was hand-rolled.
- `src/Kandoo.App/Resources/DesignTokens.xaml` is the only app design-token source and is merged once. It owns the ordered honey/ink/cream/wax/green/review palette, Vazirmatn aliases, font sizes, the 4/8/12/16/24/32 spacing scale, RTL page style, and 48dp minimum touch target. Page XAML and code-behind contain no hardcoded colors, font names, or font sizes.
- `scripts/Invoke-KandooApp.ps1` and `.github/workflows/kandoo-app.yml` run the app tests, publish self-contained Windows Release win-x64 and zip it, build Android Debug APK, and upload `kandoo-app-c40-win-x64` and `kandoo-app-c40-android-debug-apk` with seven-day retention.

## Verification boundary and Owner gate

Local review is static only; no local .NET/Python execution or device rendering is claimed. CI is the executor. Build success will not be represented as a device/UI automation result. The Product Owner must install both artifacts and check Persian shaping, RTL order, and touch targets; that Owner gate decides MAUI versus Avalonia and remains pending.
