# C-52 — کنسول فقط‌خواندنی کشف Holoo و بررسی backup

## رفتار تحویل‌شده

- کنسول مستقل `Kandoo.HolooDiscovery` برنامه‌های نصب‌شده با نام `Holoo` یا `هلو`، پوشه نصب، فایل‌های کاندید با پسوند `.mdb .accdb .mdf .fdb .db .dbf .sqlite` همراه size/date و فقط **نام** instanceهای محلی SQL Server را گزارش می‌کند. هیچ connection، query، سرویس SQL یا network API وجود ندارد.
- بررسی backup فقط با مسیر انتخابی کاربر انجام می‌شود: size و حداکثر ۱۶ بایت magic، حدس فشرده‌بودن و رمزنگاری. حدس رمزنگاری ZIP فقط `possible-zip-flag` است و اثبات محسوب نمی‌شود. تست stream ثابت کرد که خواندن از ۱۶ بایت بیشتر نیست.
- تنها write در production یک `File.WriteAllText` برای گزارش متنی انتخابی است؛ پیش‌فرض `kandoo-c52-report.txt` کنار exe است. هیچ directory یا فایل جانبی دیگری نمی‌سازد. حالت synthetic نیز symlink/reparse escape را رد می‌کند.
- دستورهای live بدون دو flag صریح `--live --manager-consent-granted` پیش از registry/file access رد می‌شوند. وجود flag اجازه جدید نمی‌دهد: استفاده واقعی همچنان نیازمند consent صریح مدیر و انتقال آن توسط PM است.

## اجرای synthetic و CI

در CI هر دو سیستم‌عامل Windows و Ubuntu، fixture تازه با نام `هلو نمونه`، هفت پسوند داده ساختگی و backup ساختگی ۴۰۹۶ بایتی ساخته شد. اجرای [41849334746](https://github.com/majid-ghanbari-dost/Kandoo/actions/runs/41849334746) روی هر دو OS سبز شد: build/test، guard با `network_apis=0 non_report_writes=0`، کشف metadata، inspection و upload گزارش `kandoo-c52-synthetic-*`. Main CI های [41849054120](https://github.com/majid-ghanbari-dost/Kandoo/actions/runs/41849054120) و [41849141031](https://github.com/majid-ghanbari-dost/Kandoo/actions/runs/41849141031) نیز سبز شدند.

**هیچ اجرای live، registry واقعی، backup واقعی یا داده Holoo واقعی در development/CI انجام نشد.**
