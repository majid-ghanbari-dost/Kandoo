# C-24 — Offline recovery and SMS provider boundary

**Scope:** exercise the existing durable Hub/Cloud path for offline issue, replay and crash recovery; retain deterministic test SMS and add a disabled Faraz seam. No UI, live SMS, credentials, or frozen-contract edits.

## Delivered

- **Offline then sync:** `C24_OfflineIssueThenSyncReplayAndReissueStayDuplicateFree` uses the real Hub API, SQLite Outbox, HTTP Cloud ingestion and public-invoice projection. Product, draft, item and issue complete while WAN transport fails; all four entries remain durable. Reconnection follows a lost Cloud response with the identical batch, producing `DUPLICATE`, then local acknowledgement and `IDLE`.
- **Idempotent re-issue:** replaying `r1-issue-1` returns the original operation sequence and display number without executing domain work or adding an Outbox entry. After sync replay, Cloud retains four operation IDs/log entries and one single-line public invoice. No duplicate operation, invoice projection or SMS charge is introduced.
- **Crash mid-issue:** `C24_HubCrashMidIssueRecoversWithoutPartialOrDuplicateIssue` performs `InvoiceService.Issue`, invoice persistence and display-watermark persistence inside the real SQLite transaction, then throws before commit. Reopen proves the invoice is still a draft, watermark/operation/Outbox writes rolled back, and the same issue operation can execute once. A later replay returns the stored response and issued hash; the next invoice receives the next gapless number.
- **SMS boundary:** the existing deterministic provider and all test SMS behavior remain in Testing. Production composition now selects `FarazSmsProvider`; `FarazSms:Enabled` defaults to `false`. Disabled use raises stable `SMS_PROVIDER_DISABLED`, surfaced by customer OTP as HTTP 503 without a fabricated provider ID. Enabling the skeleton still fails closed with `FARAZ_SMS_TRANSPORT_NOT_IMPLEMENTED`; no endpoint, credential field, secret, HTTP call or live-delivery claim exists.
