# C-33 — Read-only event-derived Hub stats v0

**Scope:** one authenticated, store-scoped `GET /v1/stores/{store_id}/stats/v0` route and generated `/openapi/v1.json` coverage. The projection writes no domain, accounting, or payment state and does not create accounting entries. Frozen contracts, including `docs/openapi.yaml`, are unchanged.

## Projection and money semantics

- The source is the store's immutable `replication_log`: successful `invoice.issue` entries select issued invoices, `Invoice.IssuedAt` supplies event time, and integer sales are the checked sum of `InvoiceItem.LineTotalRials`. `today`, `week`, and `month` each expose total `invoice_count` and `sales_rials`, plus `card_reader`, `card_to_card`, `cash`, and `unknown` payment-method buckets. Totals are gross issued-invoice amounts, not accounting revenue or profit.
- Only explicit payload values `CARD_READER`, `CARD_TO_CARD`, and `CASH` are recognized. Current production issue payloads do not record a payment method; missing or unsupported values therefore make the affected period `complete=false` and return `unknown.invoice_count=null`, `unknown.sales_rials=null`, and reason `PAYMENT_METHOD_NOT_RECORDED_OR_UNSUPPORTED`. Cash is never inferred and unknown is never a false zero. With no unknown events, known empty buckets and `unknown` are genuine zeroes and the reason is null.
- `TimeProvider` supplies UTC now. Windows are half-open in Asia/Tehran: local midnight for today, Saturday for week start, and `PersianCalendar` for Jalali month boundaries. Tests use a manual `TimeProvider`, not the existing Hub `IClock`, for stats time.

**Hub invoice currency unit:** Iranian Rial, code `IRR`, integer amounts. The exact Hub declarations are `HubInvoiceCurrency.Code` and `HubInvoiceCurrency.Unit` in `src/Kandoo.Hub/HubApiFirstEndpoints.cs`; its `HubInvoiceCurrency.InvoiceSource` value is `src/Kandoo.Core/Invoice.cs:InvoiceItem.UnitPriceRials/LineTotalRials`. This stats projection specifically sums `src/Kandoo.Core/Invoice.cs:InvoiceItem.LineTotalRials`.
