# گزارش ORDER 16 — تسک C-90

## خلاصه

تسک C-90: نرم‌افزار فروشگاه ویندوز در سطح پایلوت: صفحات مشتریان، برگشت‌ها، دستگاه‌ها و تنظیمات (سبک v2); صف تکرار با تلاش مجدد و لاج بکس وقتی اینترنت DOWN است (هیچ چیز از دست نمی‌رود، هیچ چیز دو بار ارسال نمی‌شود، ایدیمپوتنسی); setup.exe از CI با smoked نصب خودکار.

**وضعیت: PARTIAL** — بخش‌های زیر تکمیل نشده‌اند:
- صفحه برگشت‌ها (ReturnsPage) placeholder است؛ تا زمانی که API برگشت در هاب موجود باشد، پیاده‌سازی نهایی نمی‌تواند انجام شود.
- تست روی دستگاه ویندوز تمیز یک عملیات مالک است، نه رنر CI. رنر ویندوز GitHub هر بار تمیز است اما smoked installer فقط چیدمان و راه‌اندازی هاب را تست می‌کند، نه تست کامل کاربر نهایی روی دستگاه تمیز.

## صف تکرار و تلاشגם

صف تکرار با تلاش مجدد و exponential backoff در `src/Kandoo.Hub/HubCloudReplicationClient.cs` وجود دارد:
- تلاش‌های tối đa قابل تنظیم (MaxAttempts)
- لاج بکس استوانایی: Math.Min(60_000, 1_000 * (1 << (attempt - 1))) میلی‌ثانیه
- مدیریت خطاهای شبکه (RETRY_REQUIRED)، تشدید (THROTTLED)، خطاهای سرور (5xx)
- writer fencing برای جلوگیری از ارسال تکراری

## نصب‌ساز و smoked

- نصب‌ساز `Kandoo-Setup-x64.exe` بدون راه‌اندازی‌کننده جداگانه (C-95)
- smoked installer اجرا شد: نصب خاموش، چیدمان، smoked هاب روی بندر ۵۰۰۰، smoked برنامه MAUI (معمولی)

## PENDING-OWNER (تست روی دستگاه ویندوز تمیز)

مالک باید این مراحل را روی یک دستگاه ویندوز تمیز انجام دهد و نتیجه را ثبت کند:

1. دانلود `Kandoo-Setup-x64.exe` از GitHub Releases یا آرتیفakt CI
2. اجرای نصب‌ساز با دابل‌کلیک (بدون PowerShell، بدون ویرایش JSON، بدون ساخت دستی توکن)
3. در اولین اجرا، راه‌اندازی اولیهٔ فروشگاه از طریق رابط گرافیکی خود نرم‌افزار (نام فروشگاه → هاب محلی → نشست مالک → برنامه)
4. تایید ساخت و پیکربندی خودکار پایگاه داده، سرویس‌ها، تنظیمات و پیش‌نیازها
5. ورود به محیط واقعی Kandoo
6. انجام یک فروش gerçek و تایید appearances در Cloud و SMS outbox

ردیابی: مالک نتیجه را در گزارش پذیرش C-90 ثبت می‌کند.
