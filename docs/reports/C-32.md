# C-32 — Optional product purchase price

**Scope:** product model, SQLite migration, real Hub API, generated `/openapi/v1.json`, and tests. No UI or accounting-module implementation is included. Profit is only the derived product display value `unit_price_rials - purchase_price_rials`; it is never guessed or persisted.

## Delivered behavior

- `Product.PurchasePriceRials` is nullable and non-negative when supplied through catalog/API validation. `Product.ProfitRials` is null when purchase price is absent, including for pre-migration products; an explicit zero remains zero and produces profit equal to unit price. Negative derived profit is not clamped.
- The nullable `purchase_price_rials` SQLite column is added with the existing `EnsureColumn` migration path. Reads/writes, restart, and restore retain explicit values. Null purchase price is omitted from canonical restore JSON for legacy hash compatibility, and derived profit is always excluded.
- Product create, list/cascade, and PATCH projections expose both `purchase_price_rials` and `profit_rials`, including explicit JSON null. PATCH can set, replace, or clear the optional value. Legacy create payloads without the field retain their request hash.
- Generated OpenAPI exposes `purchase_price_rials` as nullable `integer`/`int64`. Swagger's MVC/minimal-API serializer-option precedence is aligned with the real snake_case wire contract; frozen `docs/openapi.yaml` was not edited.
