# Q-C98-02 — first-run Setup: the board describes a flow the sprint excludes

**Filed:** 2026-11-25 · **Lane:** C# · **Stage:** T3 stage 3 (C-96 group 1) · **Blocks:** Setup screen matching `Setup.dc.html`

## The mismatch

`docs/design/Setup.dc.html` — the specification — shows:

| Step pill | What the board asks for |
|---|---|
| ۱ اطلاعات فروشگاه | store name |
| ۲ تأیید شماره‌ی مدیر | **manager name + mobile, then an SMS verification code** (`ارسال کد تأیید`) |
| ۳ پشتیبان‌گیری | backup |

The built screen (`src/Kandoo.App/SetupWizardPage.xaml`) shows:

| Step pill | What it does |
|---|---|
| ۱ تعریف فروشگاه | store name |
| ۲ تنظیمات خودکار | starts the local Hub, creates the database and the owner session |
| ۳ پایان و ورود | opens the app |

Two problems, both real:

1. **The step names describe different work.** The board's step 2 is manager identity verification; the implemented step 2 is machine configuration. Renaming the pills to the board's words while the code does the board's *other* thing would make the screen state something untrue.
2. **The board's step 2 needs real SMS.** M-010 puts "SMS real" explicitly out of the sprint. A `ارسال کد تأیید` button could therefore only (a) do nothing, or (b) write a line to the demo outbox and present it as verification. Option (b) is a security-relevant lie inside the product's first-run wizard.

## Options

| # | Option | Consequence |
|---|---|---|
| **A** | Keep the implemented flow; **ask the PM to re-board** `Setup.dc.html` as *store info → automatic configuration → finish* | The board and the product agree for the demo; the manager-verification design waits for real SMS. Cheapest and honest. **Recommended.** |
| **B** | Implement the board literally with a **demo** verification code, labelled as such on screen (`کد تأیید نمایشی`) | Board matches; adds a step the PO must click through in every demo; needs the demo SMS (now wired) to actually show the code somewhere |
| **C** | Implement the board literally with **real SMS** | Out of sprint (M-010). Not available now. |
| **D** | Split: rename pills to the board's words, keep the implemented behaviour | **Not acceptable** — the screen would misdescribe its own steps. |

## Recommendation

**A**, and in the meantime C-96 group 1 stays **PARTIAL** exactly here rather than green-by-relabelling.

If the PM picks **B**, the work is: two extra inputs (`نام مدیر`, `شماره‌ی موبایل مدیر`), one `ارسال کد تأیید` button that calls the now-wired demo outbox, a code entry field, and a note saying it is a demo code. Roughly half a day, on this branch.

## One-line answer needed

**A, B, C, or D.**
